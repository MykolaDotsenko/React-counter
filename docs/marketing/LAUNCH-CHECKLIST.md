# Launch Checklist

## Purpose

Operational launch gate for the shopping-budget product.

Do not treat this as a generic marketing checklist. It exists to prevent promotion from getting ahead of product trust.

## Gate 1 — Product truth

Must be true before public marketing says it:

- remaining-first active trip exists
- exact EUR money implementation exists
- persistence survives reload
- persistence failure is visible
- one-hand manual add is stable
- quantity/edit/remove/undo work
- safety buffer works
- over-budget preview works
- finish trip works
- offline core works if advertised
- accessibility baseline passes

No target-only screenshot or claim.

## Gate 2 — Real-use validation

Before broad public launch:

- at least several real grocery/shopping trips completed by non-developer users
- obvious input-friction issues addressed
- no known data-loss bug
- no repeated confusion about what the hero number means
- at least some evidence users would repeat the workflow

Preferred stronger signal:

- users voluntarily return for a second trip

## Gate 3 — Brand

Before public naming lock:

- trademark/conflict search
- domain check
- social-handle check
- App Store/Google Play search
- pronunciation/spelling test
- international interpretation review
- simple recall test

CartRoom remains a working codename until this gate passes.

## Gate 4 — Store creative

Required:

- final icon
- screenshot 1: core remaining outcome
- screenshot 2: fast price input
- screenshot 3: pre-checkout warning
- screenshot 4: safety buffer
- screenshot 5: trust/local-first
- localized overlay copy where applicable
- alt text where platform supports it

No scanner screenshot until scanner ships.

## Gate 5 — Landing page

Required:

Hero:

> Know what you can still afford before checkout.

Subhead:

> Set your shopping limit, add prices as you go, and always see what’s left.

Proof:

- real product screenshot
- no account
- no bank connection
- offline only if fully true

CTA:

- Try demo
or
- Download

## Gate 6 — Measurement

Before launch traffic grows, define privacy-conscious events:

- landing visit
- store click
- app opened
- trip started
- first price added
- three prices added
- trip completed
- second trip started

Do not collect:

- actual budget
- item prices
- item names
- stores

without explicit need/privacy review.

## Gate 7 — Beta feedback questions

Ask users after a real trip:

1. What did you think the app was for before using it?
2. Did you look at “left” or “spent” more often?
3. Was adding every price annoying?
4. Where did you make a mistake?
5. Did the app change anything you bought?
6. Did you trust the total?
7. What would make you use it next week?
8. What feature did you expect but not find?

Do not ask only:

> Do you like it?

## Gate 8 — Organic launch assets

Prepare:

### Short video A

> You have €50 for groceries.

Show the budget shrinking.

### Short video B

> Checkout is the worst time to discover you’re over budget.

Show warning before checkout.

### Short video C

> Mental math after 20 items?

Show the one-number remaining view.

### Build-in-public post

Explain:

- Pulse Counter → real product
- exact integer money
- one-hand UX
- local-first reliability

This is primarily portfolio/developer audience content.

## Gate 9 — Launch channel order

Recommended:

1. existing network / testers
2. GitHub/portfolio
3. Threads/build-in-public
4. selective Reddit communities
5. short-form video
6. App Store/Google Play launch
7. Product Hunt
8. SEO content
9. paid acquisition only after retention proof

## Gate 10 — Review prompt

Do not prompt on:

- first launch
- first add
- over-budget state
- error

Potential trigger:

- second or third successfully completed trip

Follow platform review-prompt rules.

## First 30-day learning agenda

Learn:

- store conversion
- first-trip activation
- median items per real trip
- trip completion
- second-trip rate
- common correction type
- top acquisition source
- support complaints
- whether manual entry becomes too tedious

Do not optimize:

- follower count
- raw impressions
- Product Hunt rank

unless they translate to qualified use.

## Kill / pivot signals

Marketing should not hide weak product evidence.

Investigate deeply if:

- many installs but almost no first cart
- first cart but no second trip
- users repeatedly abandon after 2–3 price entries
- users cannot explain what “left” means
- checkout discrepancies undermine trust
- users consistently ask for a different primary job

## Growth-ready gate

Meaningful paid acquisition should require:

- credible store conversion
- credible activation
- credible second-trip retention
- stable product reliability
- defined monetization or strategic reason for paid growth
- enough data to estimate whether acquisition economics are sensible

Until then, organic learning is higher ROI.
