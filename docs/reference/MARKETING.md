# Marketing Reference

## Status

**SUPPORTING REFERENCE.**

This file guides go-to-market experiments and product presentation. It must not be used to infer shipped capability or to make unvalidated claims.

Current product truth comes from [../PRODUCT.md](../PRODUCT.md), [../ROADMAP.md](../ROADMAP.md) and evidence documents.

## Marketing objective

Acquire users who genuinely shop under a hard trip limit and prove that the product earns repeat use.

Do not optimise installs before activation/retention evidence.

## Primary thesis

The strongest message is the problem solved at the actionable moment:

> Know what you can still spend before checkout.

Do not lead with:

- AI;
- scanning;
- generic budgeting;
- expense tracking;
- long feature lists.

## Primary audiences

### Hard-limit grocery shoppers

Strongest fit.

Need:

- know remaining amount;
- avoid checkout surprise;
- correct cart before payment.

### Students / young adults

Potentially strong fit where grocery limits are frequent and mobile-first behaviour is natural.

### Families / larger trips

Value grows with item count and mental-arithmetic burden.

### Cash-envelope / gift-card shoppers

Clear finite-limit use case.

Do not broaden messaging to “everyone who shops” until evidence supports it.

## Message ladder

### Outcome

Know what is left.

### Mechanism

Set a limit. Add prices.

### Trust

Exact local totals, easy correction, no account required.

### Repeat value

Shop again, Recent Items and Price Memory reduce repeat work.

### Future smart capture

Barcode/OCR only enters marketing after it is shipped and demonstrated to save real effort.

## Proof hierarchy

Use claims in this order:

1. directly visible product behaviour;
2. green automated quality evidence;
3. documented physical usability evidence;
4. real-user retention evidence;
5. external reviews/testimonials when genuine.

Never promote:

- an internal timing target as measured fact;
- retention heuristics as observed retention;
- gated future features as available;
- local-first behaviour as installable PWA until PWA ships.

## Funnel

### Impression

Communicate the checkout-surprise problem.

### Store/landing view

Show the remaining-first UI immediately.

### First open

No mandatory account/onboarding.

### First trip

Reach first value quickly.

### Completion

Reinforce confidence/control, not spending celebration.

### Repeat trip

This is the key early product-validation moment.

## Activation signals

Useful product signals:

- trip started;
- first item added;
- multiple items added;
- trip completed.

Current retention-beta evidence remains local/content-minimized; marketing strategy does not authorize remote analytics.

## Retention signals

Primary:

- second-trip rate.

Supporting:

- third-trip behaviour;
- repeat-trip shortcut use;
- remembered-price reuse/current-price override;
- qualitative friction/trust feedback.

## App-store / portfolio screenshots

Recommended sequence:

1. **Core promise** — remaining amount + active trip.
2. **Speed** — Add price / keypad.
3. **Control** — reserve or over-budget consequence.
4. **Correction** — edit/Undo.
5. **Repeat value** — Shop again / remembered price.
6. Future scanner only after production validation.

Each screenshot should communicate one idea.

Avoid generic lifestyle mockups that hide the actual product.

## Store-page copy structure

1. problem;
2. core promise;
3. how it works;
4. trust/reliability;
5. repeat-use value;
6. evidence-backed differentiation.

Do not front-load technical implementation details.

## Landing page

A minimal landing page should contain:

- headline/outcome;
- product screenshot;
- 3-step explanation;
- trust/local-first note;
- repeat-use value;
- CTA appropriate to current release stage.

Do not build a large content site before product proof.

## Organic content priorities

Strong formats:

- real one-hand product demo;
- “mental arithmetic vs remaining-first” comparison;
- build-in-public engineering/product decisions;
- reliability/trust explanation;
- repeat-trip demonstration.

Avoid finance-advice content that changes the expected category.

## Channel priority

Early:

1. portfolio / direct demos;
2. focused beta recruitment;
3. short-form product demos;
4. relevant communities where rules allow genuine product discussion;
5. SEO only for specific problem intent.

Paid acquisition should remain small/experimental until retention proof.

## Paid acquisition gate

Meaningful paid spend is justified only when:

- activation is credible;
- second-trip behaviour is measured;
- store/landing conversion is understandable;
- unit economics can be evaluated.

Do not buy scale to compensate for weak repeat use.

## Experiment framework

For each marketing experiment define:

- hypothesis;
- target audience;
- one changed variable;
- primary metric;
- stop/continue rule;
- evidence quality.

Prefer small reversible experiments.

## Competitive messaging

### Versus calculators

Differentiate on:

- persistent trip context;
- remaining-first hierarchy;
- correction;
- repeat-use acceleration;
- premium mobile workflow.

### Versus finance apps

Differentiate on:

- in-store/pre-checkout timing;
- no bank/account dependency;
- one-trip focus.

### Versus grocery super-apps

Differentiate on:

- speed;
- low setup;
- no catalogue/list/recipe clutter;
- local-first trust.

### Versus scanner-first tools

Differentiate on:

- manual path always works;
- no false promise that barcode equals price;
- smart capture only when it truly saves work.

## Pricing / monetisation principle

Current portfolio/core product should demonstrate full value without monetisation friction.

If commercialised later:

- preserve useful free core;
- avoid surprise weekly subscriptions;
- charge for genuinely advanced/ongoing-cost value;
- test willingness to pay only after repeat value exists.

Possible advanced paid value may include:

- cross-device/household sync;
- expensive server-side OCR;
- long-term analytics;
- retailer integrations.

These are not current commitments.

## Ratings / reviews

Ask only after genuine product value, not immediately on first open.

Good moments may include:

- successful repeated use;
- stable completion after several trips.

Never interrupt a critical shopping interaction.

## Marketing risks

### Category confusion

“Budget” may imply banking/personal finance.

Mitigation: always anchor to **shopping trip / before checkout**.

### Feature theatre

Scanner/AI messaging can overshadow the actual product.

Mitigation: lead with current outcome.

### Trust overclaim

Marketing can outrun evidence.

Mitigation: claim only what current implementation/evidence supports.

### Generic utility perception

A simple product may appear replaceable by a calculator.

Mitigation: show remaining-first workflow, persistence, correction, repeat-use value and premium execution.

## Readiness gates

### Portfolio/private beta

Allowed when engineering quality is strong and evidence gaps are disclosed.

### Focused public beta

Requires stable core flow and a deliberate real-user learning plan.

### Store launch

Requires platform packaging/distribution work plus validated release criteria appropriate to the target store.

### Growth experiments

Require credible retention and conversion evidence.

## Marketing review checklist

- Is the message about the core user outcome?
- Are all shown features currently shipped?
- Are evidence claims actually measured?
- Does the creative show the real product?
- Does premium presentation remain honest?
- Does the message differentiate from calculators without pretending to be a finance platform?
- Are we optimising repeat value before paid scale?
